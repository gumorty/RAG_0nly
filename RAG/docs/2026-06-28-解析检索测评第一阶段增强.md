# 2026-06-28 解析、检索、测评第一阶段增强

## 本阶段目标

当前阶段不处理长上下文记忆，优先做好三件事：

1. 解析清洗：复杂 PDF/Office/Markdown/代码/HTML 表格等资料进入 RAGFlow 前尽量结构化。
2. 检索召回：把召回从简单 query variants 升级为体系化多通道框架。
3. 企业级测评：把核心指标代码化，作为后续调参、替换模型、替换解析器的回归基准。

## 已完成

### 1. 表格结构恢复增强

文件：

- `backend/app/services/table_index.py`

能力：

- Markdown pipe table 行级索引。
- HTML table 行级索引。
- 支持 `rowspan` 展开。
- 支持 `colspan` 展开。
- 支持重复父表头 + 子表头组合，例如 `Cost_City`、`Cost_Amount`。
- 支持上下文列前向填充，避免合并单元格导致后续行缺少地区、类别、章节等上下文。

作用：

复杂 PDF 经 MinerU/RAGFlow 转成 HTML/Markdown 表格后，会额外生成“表格行级检索索引”，让检索不只命中表头，也能命中具体答案行。

### 2. 多格式 fallback 解析增强

文件：

- `backend/app/services/document_normalize.py`

新增支持：

- `.docx`：段落、标题、表格提取。
- `.doc`：通过 `antiword` 尝试提取。
- `.pptx`：除文本外，也提取 slide 中的表格。
- `.md/.markdown`：保留 Markdown 结构。
- `.txt/.log/.rst`：文本转 Markdown。
- 常见代码文件：以 fenced code block 形式转 Markdown，保留语言类型。
- CSV/HTML 解码改为自动检测编码，减少乱码。

作用：

当 MinerU 失败或文件不适合 MinerU 时，仍能尽量生成可检索、可切片的 Markdown 影子文件，再交给 RAGFlow。

### 3. 体系化多路召回框架

文件：

- `backend/app/services/retrieval_channels.py`
- `backend/app/services/chat.py`

当前通道：

- `semantic`：语义召回，向量权重更高。
- `keyword_bm25`：关键词/BM25 倾向召回，词项权重更高。
- `rewrite_n`：查询改写召回。
- `synonym_expansion`：同义词/领域词扩展召回。
- `table_row`：表格行级索引召回。
- `section`：章节/小节/流程类召回。
- `title`：标题/目录/文件名召回。

融合方式：

- 每个通道独立调用 RAGFlow retrieval。
- 使用 RRF（Reciprocal Rank Fusion）进行初次融合。
- 使用 deterministic distilled ranker 做轻量精排：
  - 查询关键词覆盖。
  - 关键词距离。
  - 表格行命中 bonus。
  - 标题命中 bonus。
- 如果配置了 RAGFlow reranker，仍会通过 RAGFlow retrieval API 传入 `rerank_id`。

说明：

这里的 `keyword_bm25` 是通过 RAGFlow Elasticsearch 检索里的 term similarity 权重实现 BM25 倾向召回；后续如果要完全独立的本地 BM25，需要把 RAGFlow chunk 明细同步到本地或提供 chunk API 缓存。

### 4. 企业级测评指标代码化

文件：

- `backend/app/rag/eval_metrics.py`
- `backend/app/rag/evaluation.py`
- `scripts/run-rag-eval.py`

已实现指标：

- `recall@k`
- `precision@k`
- `MRR`
- `NDCG@k`
- `citation_readability_rate`
- `duplicate_line_count`

## 当前不足

1. 本地还没有完整 chunk 镜像。
   主链路 chunk 在 RAGFlow 内部，当前系统只拿 retrieval 返回的片段。要做更强 BM25、人工标注、chunk 级审阅，需要同步 RAGFlow chunks 到本地缓存表。

2. 同义词还是代码内置小词表。
   企业级应升级成按知识库/行业维护的词库，支持缩写、别名、实体规范化。

3. Deep Ranker 目前是确定性轻量版。
   后续应接入可配置 reranker，例如 bge-reranker、Qwen reranker 或 RAGFlow 已配置 reranker，并把收益纳入评测。

4. 图表理解仍依赖 MinerU/RAGFlow 输出。
   对复杂图表、图片图注、扫描件图表，需要增加图表摘要与图表实体提取。

5. 测评中心还没有前端页面。
   指标已经有代码基础，下一步需要做测评集管理、运行、报告和失败样例分析。

## 下一阶段建议

1. 增加本地 `retrieval_chunk_cache`，同步 RAGFlow chunk 文本、doc_id、页码、标题、分数元数据。
2. 基于 chunk cache 增加真正本地 BM25 通道，与 RAGFlow semantic/term retrieval 做 RRF。
3. 增加领域词库表：同义词、缩写、实体别名、停用词。
4. 增加测评数据库表：`evaluation_datasets`、`evaluation_cases`、`evaluation_runs`、`evaluation_results`。
5. 前端增加“测评中心”：选择知识库、选择测评集、运行、查看 recall/MRR/NDCG/faithfulness/引用可读率、定位失败样例。
