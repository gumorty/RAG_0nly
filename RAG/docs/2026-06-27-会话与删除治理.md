## MinerU 接入判断

本轮没有把 MinerU token 写入仓库。原因：

- 当前缺口是知识库和会话生命周期治理，和 MinerU API 无直接依赖。
- MinerU token 应通过后端配置或模型/解析引擎配置保存，不应硬编码在代码里。
- MinerU 更适合作为后续 `ParseEngine` 插件接入，用于复杂 PDF、扫描件、跨页表格和 OCR。

建议下一阶段新增：

```text
backend/app/services/parse_engines/
  base.py
  ragflow_native.py
  mineru_engine.py
  parse_router.py
```

并通过配置启用：

```env
MINERU_ENABLED=true
MINERU_BASE_URL=...
MINERU_API_KEY=...
MINERU_TIMEOUT_SECONDS=300
MINERU_TRIGGER_EXTENSIONS=.pdf,.png,.jpg,.jpeg
```

接入原则：

- 普通文档继续走 RAGFlow DeepDOC。
- 复杂 PDF / 扫描件 / 表格型 PDF 可走 MinerU。
- MinerU 输出不能直接丢进向量库，应先转换为 table summary、row chunks、cell metadata，再进入 RAGFlow 或自建表格索引。
