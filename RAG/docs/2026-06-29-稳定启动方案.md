# 2026-06-29 稳定启动方案

## 本次启动失败原因

Windows 当前保留了多个 TCP 端口段，其中包含：

- `7998-8097`
- `13294-13393`

旧配置中：

- 管理系统 API 使用 `8010:8000`，落在 `7998-8097` 范围内。
- RAGFlow MySQL 使用 `13306:3306`，落在 `13294-13393` 范围内。

这些端口可能被 Windows / Hyper-V / WSL / Docker Desktop 保留，Docker 绑定时会报：

```text
ports are not available: bind: An attempt was made to access a socket in a way forbidden by its access permissions
```

## 推荐启动命令

以后从项目根目录执行这一条即可：

```powershell
cd D:\Researching\LLMStart\RAG
powershell -ExecutionPolicy Bypass -File scripts\start-all.ps1
```

脚本会执行：

1. 检查 Docker 是否可用。
2. 检查关键端口是否落入 Windows 保留端口段。
3. 启动 RAGFlow 官方引擎容器。
4. 启动管理系统的 PostgreSQL、Redis、MinIO、API、Frontend。
5. 检查 API 和前端是否可访问。

## 修改代码后的重启命令

只改后端：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev-restart.ps1 -Service api
```

只改前端：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev-restart.ps1 -Service frontend
```

前后端都改了：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev-restart.ps1 -Service all
```

需要完全无缓存重建：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev-restart.ps1 -Service all -NoCache
```

## 常用排查命令

查看管理系统容器：

```powershell
docker compose ps
docker compose logs --tail=120 api frontend
```

查看 RAGFlow 容器：

```powershell
cd D:\Researching\LLMStart\RAG\external-repos\ragflow\docker
docker compose --profile elasticsearch --profile gpu ps
docker compose --profile elasticsearch --profile gpu logs --tail=120 ragflow-gpu
```

查看 Windows 保留端口段：

```powershell
netsh interface ipv4 show excludedportrange protocol=tcp
```
