# 2026-06-27 PDF 表格错答与上传 500 修复

## 问题一：PDF 宽表格导致模型错答

根因：

- RAGFlow/DeepDOC 已经完成 PDF 表格解析，但复杂宽表会被压平成长行或 HTML 表格片段。
- 旧逻辑只对超过 5200 字的片段做实体行筛选，较短但含多地区数据的表格会原样进入模型。
- 表格里青海、海南、西藏等地区存在“旺季/上浮”字段，而新疆行没有这些字段，模型容易把相邻地区字段错套到新疆。

修复：

- `backend/app/services/chat.py` 的证据聚焦改为表格优先。
- 只要片段像表格，即使只有 2-3 行也按问题实体筛行。
- 识别到“新疆”等地区时，仅使用地区实体族命中，例如新疆、乌鲁木齐、石河子、克拉玛依、昌吉、伊犁、阿克苏、喀什等。
- “旺季/浮动/上浮/标准”等泛化词不再用于选中表头。
- 超长表格行只保留实体附近窗口，不再把整张宽表塞给模型或前端引用。
- 如果相关行没有“旺季/浮动/上浮”字段，会在证据上下文中明确提示模型必须说明证据不足。

验证：

- 容器内测试：`18 passed, 1 warning`。
- 真实企业知识库问题：“新疆有哪些地区在旺季期间有浮动吗？浮动了多少？”
- 当前回答：证据未提供新疆旺季浮动/上浮金额，不能推断具体浮动。
- 当前引用：仅保留新疆相关行与政策原文，不再混入青海、海南或整张表。

## 问题二：上传文件时 API 500 / Failed to fetch

根因：

- `api` 容器同时连接本项目网络和 RAGFlow 网络。
- 两个网络里都有服务别名 `minio`。
- `MINIO_ENDPOINT=minio:9000` 实际解析到了 RAGFlow 的 MinIO，而不是本项目 MinIO。
- 本项目 MinIO 凭据访问 RAGFlow MinIO 被拒绝，后端抛出 `InvalidAccessKeyId`，上传接口返回 500，前端表现为 `Failed to fetch`。

修复：

- 本项目 MinIO 增加唯一网络别名 `llmstart-minio`。
- `.env` 中 `MINIO_ENDPOINT` 改为 `llmstart-minio:9000`。
- 避免与 RAGFlow 的 `docker-minio-1` 服务名冲突。

验证：

- `docker exec rag-api-1 getent hosts llmstart-minio minio`
- `llmstart-minio` 指向本项目 MinIO。
- `minio` 仍指向 RAGFlow MinIO。
- 新建临时知识库 `codex-upload-smoke-*`，通过 `/api/collections/{id}/documents` 上传 `ARCHITECTURE_DECISION.md` 返回 200。
- 轮询后文档状态为 `ready`，`ragflow_progress=1.0`，生成 2 个分块。

## 当前最佳处理策略

短期继续由 RAGFlow 负责文档解析、分块、向量索引和混合检索；我们的管理层负责证据标准化、表格行级保护、引用可读化和答案后验约束。

中期需要升级为“表格行/单元格级 chunk + 表头继承 + 页码/坐标引用”。对于复杂 PDF、扫描件、跨页表格和大量 Excel/PPT/HTML，建议引入专门的表格结构化处理链路，并把结构化表格作为独立可检索证据入库，避免仅靠文本窗口处理复杂表格。
