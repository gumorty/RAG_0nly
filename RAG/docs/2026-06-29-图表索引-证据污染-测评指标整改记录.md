# 2026-06-29 图表索引、证据污染与测评指标整改记录

## 背景

本轮整改参考了 `D:\Researching\LLMStart\当前系统实际表现怎么样？问题是什么.md` 中基于 `P020241210548865982463.pdf` 的测试观察，但最终以当前代码和自动化测试结果为准。

核心问题集中在三类：

1. 非差旅文档的长表格证据中被注入“旺季/上浮/相邻地区”这类差旅住宿费规则，形成证据污染。
2. 图表类问题主要依赖目录、图题附近文本和普通语义召回，缺少独立的图号/页码/图题索引，容易出现图6/图7问答定位不稳。
3. 测评中心只有 recall/MRR/NDCG/引用可读率，无法显式观察证据污染、目录过排和图表问题命中情况。

## 已完成修改

### 1. 证据污染控制

修改文件：

- `backend/app/services/chat.py`

处理方式：

- `_focus_evidence_for_question()` 不再对所有表格片段统一注入“旺季/上浮/相邻地区”提示。
- 仅当问题和证据满足差旅住宿费政策上下文时，才启用该保守提示。
- 对“表格行级检索索引”的 `表格N 第N行：字段=值` 格式进行识别，避免只有少量行时直接原样返回，导致无关表格行混入答案上下文。
- `广西` 差旅表格修复逻辑增加领域条件，避免迁移到非差旅材料。

### 2. 图表检索索引

新增文件：

- `backend/app/services/figure_index.py`

修改文件：

- `backend/app/services/parser_router.py`
- `backend/app/services/mineru.py`

处理方式：

- 在 Markdown 入库前追加 `# 图表检索索引`。
- 从图题、图目录、Markdown 图片引用和邻近段落中抽取：
  - 图号
  - 图题
  - 页码线索
  - 图片引用路径
  - 邻近文本
- MinerU 结果包现在记录 artifact 元数据，包括图片、JSON、表格/布局文件数量和样例路径。

注意：

- 当前图表索引是文本和结构线索增强，并不是完整 VLM 读图。若要回答“图中某个曲线/柱子具体数值”，后续还需要把 MinerU 图片资产落盘、建立图片页码映射，并接入 VLM 或图表结构化抽取。

### 3. 图表召回与重排

修改文件：

- `backend/app/services/retrieval_channels.py`

处理方式：

- 增加 `figure` 意图识别。
- 增加 `figure_index` 检索通道，查询图号、图题、页码、图片、邻近文本等结构字段。
- RRF 后的确定性 ranker 对图表索引、明确图号、页码线索增加权重。
- 对纯目录类片段增加过排惩罚，降低“目录命中但正文证据不足”的概率。

### 4. 企业级测评指标补充

修改文件：

- `backend/app/rag/eval_metrics.py`
- `backend/app/api/routes.py`
- `frontend/app/page.tsx`

新增指标：

- `evidence_pollution_rate`：证据污染率，当前先用于发现非差旅问题中混入差旅住宿费术语。
- `toc_over_rank_rate`：目录过排率，观察 Top-K 中目录片段过多的问题。
- `figure_hit_rate`：图表命中率，图表类问题至少应命中图表索引或非目录图号片段。

前端测评中心已展示这些新增指标。

## 当前仍不足

1. 图表理解仍主要依赖 MinerU Markdown、图题和邻近文本；尚未把图片资产、版面 JSON、页码坐标做成可点击原文定位。
2. 表格复杂结构已经有 rowspan/colspan 展开和行级索引，但跨页表头继承、表格标题到数据区域绑定仍需要继续增强。
3. 当前测评指标是确定性规则底座，适合回归和定位问题；faithfulness 仍需要引入 LLM-as-judge 或人工标注样例来提高可信度。
4. 已上传并解析完成的旧文档不会自动拥有新的图表索引，需要重新导入或后续增加“重建解析增强索引”的后台任务。

## 下一步建议
